## Environment notes

- `next dev` grew past 3 GB inside one UI batch and the machine's memory
  pressure killed the stack twice; the full run therefore uses a production
  build of the client (`docs/test-plan.md` §1).
- Another Ducker ID server on the same Redis shares the BullMQ queues and
  steals notification jobs — none was running during this run.
- An earlier, abandoned attempt ran against the developer database
  `ducker-id`; its residue (login history, contacts, throwaway accounts,
  orphan notifications, a changed seed account) was removed and the seed
  account restored. `user.setup.ts` now refuses any database that is not the
  seed.
